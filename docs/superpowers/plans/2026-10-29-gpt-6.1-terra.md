> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make terra a current tier served by `gpt-6.1-terra` (native `claudex:gpt-terra` agent, `claudex:relay-terra` courier, terra worker tier) for straightforward, well-specified code, and retire `gpt-5.6-terra` completely.

**Architecture:** The proxy already resolves terra from the live catalog; Task 1 fixes its fallback table and locks the 5.6 retirement in tests. Tasks 2–4 remove the "terra is sol" alias from `claudex-worker`, the mod and the docs, and add the terra agent, courier and routing guidance. Tasks 1–4 touch disjoint files and run in parallel; Task 5 is verification, review and commit in the main session.

**Tech Stack:** C17 (yyjson, ASan/UBSan unit tests via `make`), Bash (`claudex-worker`, bash test scripts), TypeScript Claude Code mod (`claude plugin test`), Markdown skills.

**Spec:** `docs/superpowers/specs/2026-10-29-gpt-6.1-terra-design.md`

## Global Constraints

- Tier order everywhere a list is shown or registered: `luna, terra, sol, astra`. Exceptions: the proxy's family index order (`LUNA, SOL, ASTRA, TERRA`), `/healthz`, `/v1/models` and the `models:` lines keep `luna, sol, astra, terra`.
- Terra default effort: `medium`. Sol `high`, luna `low`, astra `xhigh` (unchanged).
- Terra role text (agent description, verbatim): `Straightforward, well-specified code: mechanical edits, small fixes and tests from an exact spec; complex multi-file work and debugging go to sol.`
- Sol role text (agent description, verbatim): `Complex multi-file implementation, refactors and debugging, and any code task that is not clearly straightforward.`
- `gpt-5.6-terra` must never be the resolved upstream slug, whatever the catalog or rejections. It is enforced by a retired-slug list in `src/models.c`, which takes precedence over generation ranking; the name stays accepted as input.
- Default `CLAUDEX_TIERS=luna,terra,sol,astra`; default `CLAUDEX_DEFAULT_WORKER=sol`.
- No "terra is deprecated" text anywhere outside historical records (`SPIKES.md`, `PROTOCOL.md`, older specs/plans, `tests/skills/`).
- Plugin version `0.5.0`.
- **Workers do not commit.** Tasks 1–4 run in parallel in one working tree; the main session commits in Task 5.
