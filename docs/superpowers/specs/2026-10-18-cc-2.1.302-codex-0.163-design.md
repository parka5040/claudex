# claudex on Claude Code 2.1.302 and Codex 0.163.0 — design

Status: approved for planning, 2026-10-18. Supersedes the 2.1.288 assumptions in
`2026-10-03-publish-agents-lineup-design.md` where they conflict. Plugin version becomes 0.4.0.

## Goal

1. Run correctly on Claude Code 2.1.302 and codex-cli 0.163.0.
2. Make GPT agents (`claudex:gpt-luna|sol|astra`, including GPT-6.1 Sol) visible the way native
   Claude agents are, wherever the mod controls what is shown.

## What was verified live (2026-10-18, Claude Code 2.1.302, codex-cli 0.163.0)

Three PTY probes (200×50, pyte) ran one `claudex:gpt-luna` agent beside one native
`general-purpose` agent, with the repo plugin loaded through `--plugin-dir`. Two more checks ran
in an interactive session: ListAgents and SendMessage.

| Surface | GPT agent | Native agent |
|---|---|---|
| Footer agent list while running (type, description, time, ↓ tokens) | listed, same | listed |
| Footer list after completion, not viewed | dropped, same | dropped |
| Footer list after completion, while its view is open | kept, same | kept |
| Transcript view (Enter): prompt, Trail, Edit diff, live activity | same | same |
| `/tasks` model column | **`gpt-luna (low)`**, the bare alias | `Haiku 5.5` |
| ListAgents rows, running then completed | same | same |
| SendMessage resume of a completed agent; Read inside its cwd | works | works |
| claudex status line while a GPT agent runs | **`claudex: idle`** | n/a |

`plugin/tests` passes 73/73 on 2.1.302 and `claude plugin validate plugin` passes.

## Problems to fix

### Visibility (mod-controlled)

- **V1, model label.** `agent.spawn` rewrites `model` to the alias `gpt-<tier>`, and the alias is
  what `/tasks` shows. The proxy knows the resolved slug (`/healthz` `models.<tier>`, e.g.
  `gpt-6.1-sol`). Spawn with that slug so `/tasks` reads `gpt-6.1-sol (high)`. The registered
  agent definition keeps the alias, because resolution changes over time.
  - The slug comes from a new `claudex-worker model TIER`.
    - It checks the switch and the tier first, then makes sure the proxy is running, then prints
      `{"model":"<slug>"}` from `/healthz` if the proxy is ours.
    - On any failure it prints nothing.
  - The hook runs it *before* taking the admission lock, with a 5000 ms process timeout,
    because hooks have a 10 s budget and time spent waiting on another spawn's promise counts
    against it. The admission-lock wait stays 5000 ms. `admit` is unchanged.
  - If the probe yields nothing, the label falls back to the last status's `models.<tier>`, then
    to the alias.
- **V2, status line.** `record()` and the pruning in `agents.ts` change `live.agents`, but
  nothing redraws the status line or moves polling from the 60 s idle cadence to 2 s. A GPT agent
  shorter than a minute never shows as running. Every change to `live.agents` must redraw the line
  and re-arm polling.

### 2.1.302 API semantics

- **A1, statuses.** `AgentInfo.status` is now
  `'pending'|'running'|'waiting'|'idle'|'completed'|'failed'|'killed'`. The mod treats anything
  other than `running` as gone: the tick prunes `pending`, `waiting` and `idle` agents, losing
  `cwd`, `prompt` and signed thinking. A later step then rediscovers the agent with `cwd: null`,
  and confinement denies every file tool. Statuses split into three groups:
  - *Live* (keep the entry): `pending`, `running`, `waiting`, `idle`.
  - *Active* (counts toward `CLAUDEX_MAX_PARALLEL`): `pending`, `running`, `waiting`.
  - *Ended*: the rest.
- **A2, spawn kinds.** `agent.spawn` now also fires for resumed runs (`e.resume`), teammates
  (`e.isTeammate`) and Workflow agents (`e.workflow`).
  - **Resume:** admit as usual, but do not rewrite `model` (a rewrite is ignored and reported as
    a failure line).
    - **Metadata source.** Confinement metadata (tier, cwd, mode, prompt) lives in a *retained*
      map, separate from the live registry. It is written whenever an agent is recorded, never
      pruned by the tick, capped at 256 entries (oldest out), and published as the state key
      `claudex.retained`. A resume takes `cwd` and `prompt` from the live entry, else from the
      retained one. With neither, the resume is denied:
      `claudex: cannot resume GPT agent <id>: its confinement metadata is gone; spawn a new agent`.
      It never guesses the session cwd.
    - **Mode.** The resumed `mode` is `read` if either the retained mode or the current policy is
      `read`, so a resume never widens.
    - **Registration is transactional.** The id joins a `resuming` set that the tick never
      prunes. A provisional live entry is recorded *before* `next(e)`, because steps may run
      before `next` resolves, with `final` reset to null. If `next` denies or throws, the previous
      live entry is restored, or the provisional one removed.
    - **Rediscovery.** When `lookupAgent` rediscovers a listed GPT agent it no longer has, it uses
      retained metadata before falling back to `cwd: null`.
  - **Read mode at execution.** `confine.ts` denies `Write` and `Edit` for read-mode agents. Today
    only Bash enforces mode, and the advertised tool list is not a guarantee.
  - **Workflow:** deny before admission with
    `claudex: GPT agent types cannot run as Workflow agents; use claudex:relay-<tier> in Workflow scripts`.
    Workflow agents never appear in `$.agent.list()`, so today the tick prunes them within 2 s
    and their next step falls through to the Anthropic API as `gpt-<tier>` (404).
  - **Teammate:** deny before admission with
    `claudex: GPT agent types cannot join a team yet; spawn them as subagents`.
    Their idle/wake/handback lifecycle is untested with GPT steps, and a teammate in its own
    terminal pane runs no loop in this process.
- **A3, types.** Since a mod was loaded through `--plugin-dir`, the engine writes
  `plugin/.claude-plugin/types/` (gitignored) and `plugin/tsconfig.json`. `make plugin-check`
  then prefers `claude-code/index.d.ts`, which lacks the built-in tool inputs (they moved to
  `claude-code-tools/index.d.ts`), so `confine.ts` fails the check with 4 errors. Type-check
  against the concatenation of both files. Gitignore `plugin/tsconfig.json`.
- **A4, tool schemas.** The live 2.1.302 capture
  (`spikes/native-agents/tool-schemas-2.1.302.json`) differs from 2.1.288 in two places:
  - `Read` gained `allow_large`.
  - The `Bash` description and one property description changed.

  Regenerate `plugin/hooks/tool-schemas.ts` from the capture. `claude -p` now sends two
  requests, so `tests/live/capture_tool_schemas.sh` must keep one copy of each tool.

### Codex 0.163.0 (openai/codex `595cc91e8` → `rust-v0.163.0` = `83086188a`)

Nothing found in source breaks the proxy. Endpoint, auth headers, `auth.json`, the rate-limit
headers and the `/models` fields the proxy reads are unchanged. Adopted:

- **C1.** The default `client_version` for `/models` becomes `0.163.0` (`src/upstream.c`). The
  installed CLI's version still wins when known.
- **C2.** Top-level `instructions` was removed from the client in 0.162.0 (commit `c9253c497`).
  Base instructions now travel as a leading `{"type":"message","role":"developer","content":[{"type":"input_text","text":…}]}`
  item of `input` (`core/src/client.rs@83086188a:996-1006`). The proxy does the same. It keeps
  dropping the billing-header system block and joining the blocks with a blank line, and sends no
  `instructions` key.
- **C3.** Serialize `model` and `stream` before `input` (commit `ed0cc1a4a`: gateways may inspect
  bodies incrementally).
- **C4.** A new top-level SSE event `{"type":"error","error":{code,message}}` maps through the
  same code table as `response.failed` instead of ending as "stream closed before
  response.completed".
- **C5.** `response.incomplete`:
  - `max_output_tokens` → `max_tokens`
  - `content_filter` → `refusal` (both unchanged)
  - `interrupted` → an `overloaded_error` stream error (status 529)
  - any other or missing reason → an `api_error` stream error (status 500)
    `upstream response incomplete: <reason>`

  Today the last two end the turn silently. Non-streaming clients get these through
  `collect.c`'s existing mapping: 529 and 502. Headless `claude -p` workers retry a 529 as Claude
  Code retries any overload. Native GPT agent steps hand the error back, as for every upstream
  error today. A step-level retry policy for native agents is future work.

### Proxy DNS after a resolver change (found while planning)

- **P1.** On 2026-10-18 the proxy (started 04:10) failed every request from 13:54 with
  `Could not resolve host: chatgpt.com`, after `/etc/resolv.conf` was rewritten at 13:54. Host
  DNS kept working.
- Landlock path rules attach to the inode opened when the ruleset is built.
  `src/sandbox.c:97` adds rules for the *files* `/etc/resolv.conf`, `/etc/hosts`,
  `/etc/nsswitch.conf`, `/etc/gai.conf` and `/etc/host.conf`. A file replaced by rename (the way
  NetworkManager, dhcpcd, VPN clients and systemd-resolved rewrite them) is a new inode, so the
  proxy loses read access until it restarts.
- Fix:
  - **Keep the five file rules.** They cover external symlink targets, e.g. NixOS `/etc/hosts`
    into the store.
  - **Add a read rule beneath `/etc`.** It covers files replaced inside `/etc`. Allowing
    `/etc/passwd` and the like is acceptable: they are world-readable already, and the sandbox
    protects the token, not public system files.
  - **Add the symlink target's parent, from an allowlist only.** When `/etc/resolv.conf` is a
    symlink, add a read rule beneath its resolved target's parent, but only if that parent is one
    of `/run/systemd/resolve`, `/run/NetworkManager`, `/run/resolvconf`, `/run/connman`,
    `/run/netconfig` or the same names under `/var/run`. Any other parent (`/`, a home directory,
    `/tmp`, `/run`, `/run/user/N`, …) gets no directory rule. Those layouts keep today's
    behaviour: the file rule, and a restart after a rewrite.
  - The directory rules already in place (TLS stores, the Codex auth directory) are unaffected.
- The README's sandbox sentence changes accordingly.

Not adopted: passing `Retry-After` through (a long usage-limit `Retry-After` would stall Claude
Code silently), `encrypted_content` output replay (off by default upstream), and `phase` values.

## Out of scope

Native GPT agents inside Workflow scripts, and GPT teammates, are denied for now with a pointer
to the supported path. GPT text arriving per step rather than streamed (2.1.288 gate item 3) is
not re-measured here; the transcript view showed live tool activity identical to native.
Desktop, VS Code and mobile surfaces were not probed.
