# GPT-6.1 Terra agents — design

Status: approved for planning, 2026-10-29. Supersedes the terra parts of
`2026-10-03-publish-agents-lineup-design.md` ("Terra: deprecated, served by sol"). Plugin version
becomes 0.5.0.

## Goal

1. Terra is a current tier again, served by `gpt-6.1-terra`: a `claudex:gpt-terra` native agent,
   a `claudex:relay-terra` courier, and a terra worker tier in `claudex-worker`.
2. Terra's role is **straightforward, well-specified code**: mechanical edits, small fixes and
   tests from an exact spec. Sol keeps complex multi-file implementation and debugging, and stays
   the default worker.
3. `gpt-5.6-terra` is completely retired: claudex never sends a request to it.

## What was verified live (2026-10-29, codex-cli 0.165.0)

- The backend catalog (`~/.codex/models_cache.json`, fetched 2026-10-29T15:46Z) lists
  `gpt-6.1-terra`: `visibility: list`, `supported_in_api: true`, priority 3, efforts
  `low..ultra`, Codex default `low`. It also still lists `gpt-5.6-terra` (priority 8).
- The current proxy, unchanged, already resolves it: after its catalog fetch `/healthz` reports
  `"terra":"gpt-6.1-terra","source":"backend"`. Before the fetch (fallback table) it reports
  `"terra":"gpt-6.1-sol"`.
- Everything above the proxy still treats terra as a sol alias.

## Behaviour

### Model lineup (proxy, `src/models.c`)

- The resolution rule is unchanged: a family is current while it has a served model of the newest
  generation (highest served major version) and resolves to its highest-version served model;
  otherwise it resolves to what sol resolves to.
- Fallback table: terra → `gpt-6.1-terra`. In fallback mode terra counts as current like the
  other families (the `i != TERRA` exclusion is removed). If the backend rejects
  `gpt-6.1-terra`, the existing rejected-model path makes terra resolve to sol.
- Terra's default effort stays `medium`. No clamp (terra supports `ultra`).
- `/v1/models` lists the four current families' slugs in family order luna, sol, astra, terra.
- **5.6 retired.** Any terra name, including `gpt-5.6-terra`, resolves to the current terra or,
  failing that, to sol. `gpt-5.6-terra` itself is never the resolved slug. The generation rule
  alone is not enough: it ranks only unrejected rows, so rejecting every 6.x model (or a
  generation-5-only catalog) would make 5.6 terra current. `src/models.c` therefore keeps a
  retired-slug list (`gpt-5.6-terra`) and `models_catalog_load` drops those rows, so they are
  never candidates. Retirement takes precedence over generation ranking. The slug stays
  accepted as an input name.

### Worker (`plugin/bin/claudex-worker`)

- Terra is its own tier and its own gate. `tier_enabled terra` checks for `terra` in
  `CLAUDEX_TIERS`; `sol` no longer passes when only `terra` is listed, and vice versa.
  `slug_tier` maps `*-terra` to `terra`, so an adversary model of `gpt-terra[@e]` is gated by
  terra.
- Default `CLAUDEX_TIERS` becomes `luna,terra,sol,astra`. `CLAUDEX_DEFAULT_WORKER` stays `sol`.
- `tier_default_effort terra` is `medium`, and a headless terra run without `--effort` sends
  `gpt-terra@medium` like every other tier (the bare-`gpt-terra` special case is removed).
  Claude Code's headless requests carry their own `output_config.effort` (`high`), which the
  proxy honours over a family default, so a bare alias ran terra at `high` (verified live
  2026-10-29). When terra falls back to sol, a headless terra run uses sol at `medium`. Native
  agent steps send no body effort, so the proxy's default for the family they resolve to
  applies: `medium` while terra is current, sol's `high` when terra falls back to sol. The
  resolution rule is unchanged; the two paths differ only in that fallback case.
- The static deprecation warning goes: `terra_deprecated` is deleted, the policy line and
  `status` no longer print "terra is deprecated (served by sol)", and `status --json` always
  emits `"deprecations":[]` (the field stays for the mod's generic rendering). Instead the
  `models:` line in `status` and the policy line gain `terra=<slug>`, so a fallback shows as
  `terra=gpt-6.1-sol`.
- Messages and usage text that say "luna, terra, sol or astra" stay valid as written; the usage
  line drops nothing.
- **Breaking change for old settings**, documented in the README: a setting that lists terra but
  not sol (for example `CLAUDEX_TIERS=luna,terra,astra`) used to enable sol and now enables terra
  only. `CLAUDEX_DEFAULT_WORKER=terra` now means terra. The reverse also changes: an explicit
  tier list without terra (for example the old default `luna,sol,astra`) used to admit
  `CLAUDEX_DEFAULT_WORKER=terra`, `CLAUDEX_ADVERSARY_MODEL=gpt-terra…` and `run terra` as sol;
  those are now refused until terra is added to the list (or sol is named instead). The alias
  gate is not restored.

### Mod (`plugin/hooks`)

- `Tier` becomes `'luna' | 'terra' | 'sol' | 'astra'`; registration order `luna, terra, sol,
  astra`.
- `claudex:gpt-terra` registers with effort `medium`, model `gpt-terra`, the same tools, prompts
  and `maxTurns` as the others, and the description *"Straightforward, well-specified code:
  mechanical edits, small fixes and tests from an exact spec; complex multi-file work and
  debugging go to sol."* followed by the shared "Runs on GPT through claudex…" sentence.
- `claudex:gpt-sol`'s description becomes *"Complex multi-file implementation, refactors and
  debugging, and any code task that is not clearly straightforward."* (it no longer claims all
  code writing).
- `enabled(tier)` is `configured.includes(tier)`; the terra→sol mapping is removed.
- The published state contract `plugin/types/index.d.ts` (`ClaudexAgent.tier`,
  `ClaudexRetained.tier`) gains `terra`, mirroring `hooks/agents.ts`.
- `/claudex status` shows `terra=<slug>` in its Models line. `ClaudexStatus.models` already has a
  `terra` field.
- The Workflow-deny message already names `claudex:relay-${tier}`, which now exists for terra.

### Courier (`plugin/agents/relay-terra.md`)

Same body as `relay-sol.md` with `claudex-worker start terra`. Description: *"Couriers
straightforward, well-specified code (mechanical edits, small fixes and tests from an exact spec)
to the terra GPT worker; complex multi-file work goes to claudex:relay-sol."* followed by the
shared policy, brief and "For Workflow scripts… use claudex:gpt-terra" sentences.
`relay-sol.md`'s description changes to match sol's narrower role and points straightforward
code at `claudex:relay-terra`.

### Skills and docs

- `delegating-to-gpt/SKILL.md`: tier lists name terra; the tier table gains
  `terra | straightforward, well-specified code: mechanical edits, small fixes, tests from an exact

  The "`terra` is deprecated…" sentence becomes: send contained, well-specified code to `terra`;
  complex multi-file implementation and debugging to `sol`; when unsure, `sol`; brief `astra` to
  review, not to edit files.
- `delegate/SKILL.md`: argument hint `<luna|terra|sol|astra>`; the "Terra is deprecated" line

- `status/SKILL.md`, `config/SKILL.md`: default tiers `luna,terra,sol,astra`; deprecation text
  goes.
- `README.md`: model families, fallback table, defaults (terra medium), roles paragraph, the
  `CLAUDEX_TIERS`/`CLAUDEX_DEFAULT_WORKER` rows, the agents line, the breaking-change note, and a
  sentence that `gpt-5.6-terra` is never used.
- `PLAN.md`: lines 13, 18, 40, 71 updated to the four-tier lineup.
- Historical records (`SPIKES.md`, `PROTOCOL.md`, earlier specs and plans) and the skill eval

- `plugin/.claude-plugin/plugin.json` version 0.5.0.

## Build

Design and plan in the main session. Implementation and tests by `claudex:gpt-sol` agents;
plan and diff review by the Astra adversary (`mcp__claudex__review`). The main session audits
any test script a worker will run for unchecked temp dirs and `rm -rf` on variables, runs
`make check` itself, and verifies with `git diff`.
